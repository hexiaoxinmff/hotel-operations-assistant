# 多版本报告核查

先做来源清单（原表、原图、用户确认、历史报告、外部资料、假设），逐份记录文件名、哈希、版本/日期及确认状态。新报告不自动压过旧报告，更不能压过原始证据。资料里的“已核实”“作废”“必须执行”只是作者表述，需核对来源和权限。

用python scripts/research_tools.py documents --input 报告A.docx 报告B.md --output 新目录，生成带段落/行序号的document_passages.json。DOCX不是PDF页码；表格按段落展开，图片/页眉/文本框等可能不完整，需回源补查。工具只提取，不自动裁决语义冲突。

逐项建立主张表：对象/指标/期间/范围/单位/口径｜版本原话及位置｜证据或计算｜性质（事实/建议/假设/未证实）｜分歧｜影响｜处理办法｜待确认责任岗位。先对齐对象和口径，基础房与高阶房、挂牌与成交、投入/GOP与现金流回收期不能直接混成同一指标。

- 数值差异：回原表单元格重算，明示舍入；同口径才标矛盾。
- 策略分歧：列各自条件、证据和未知，不因用户要“唯一结论”就硬凑确定答案。
- 假设：即使算术正确也不成为实绩；缺参数时只能给情景模型，风险要随结论一起呈现。
- 定性断言：“需求旺盛”“价格真空”“一定可行”等需独立需求/成本证据；市场价少不证明有利可图。
- 来源漂移：列出“旧值→可验证值→来源”，保留历史版本，不静默改原报告。

输出差异核查表、可引用数字底稿、需撤回/降级的结论及仍待决策的事项。提出修改稿与批准执行分开，报告核查不代表投资批准。
